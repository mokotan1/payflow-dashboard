# Payflow Dashboard

Gmail에서 정기결제 관련 메일을 찾아 결제 예정 목록, 결제 현황, 주의가 필요한 항목을 한곳에서 관리하는 데스크톱 앱 프로젝트입니다.

> 현재 저장소는 기획 단계입니다. 실제 Gmail 또는 결제 서비스와 연결되는 코드는 아직 포함하지 않습니다.

## 제품 목표

사용자는 여러 서비스의 청구 메일과 결제일을 직접 찾아다닐 필요 없이 다음 정보를 한 화면에서 확인할 수 있습니다.

- 이번 달 정기결제 총액과 남은 결제 예정액
- 결제 완료, 결제 예정, 확인 필요, 연체 상태
- 다음 결제일과 사용 중인 결제수단
- Gmail에서 새로 발견된 구독 및 청구 정보
- 서비스 결제 페이지 이동 또는 앱 안에서의 직접 결제

## 핵심 사용자 흐름

1. 사용자가 Google 계정을 연결합니다.
2. 앱이 Gmail의 결제·청구 관련 메일을 읽고 정기결제 후보를 추출합니다.
3. 사용자가 후보를 확인하고 정기결제 목록에 추가하거나 제외합니다.
4. 대시보드에서 월별 금액, 결제일, 상태와 주의사항을 확인합니다.
5. 필요한 경우 서비스 결제 페이지로 이동하거나 앱 안에서 결제를 요청합니다.
6. 직접 결제는 결제처, 금액, 결제수단을 다시 확인한 뒤에만 실행됩니다.

## 선택된 UI 방향

### 스마트 월렛

구독 서비스를 카드 형태로 보여주는 금융 지갑 스타일을 채택합니다.

- 데스크톱 우선 레이아웃
- 월간 총액과 결제 현황을 크게 표시
- 서비스별 금액, 결제일, 상태와 결제수단 제공
- 검색 및 상태 필터
- Gmail 동기화 상태 표시
- 데스크톱 안정화 후 모바일 앱으로 확장하기 쉬운 카드형 구조

## 기능 범위

### 1단계 — 데스크톱 MVP

- Google OAuth 로그인
- Gmail 읽기 권한 연결 및 해제
- 결제·영수증·구독 메일 탐지
- 정기결제 후보 검토 및 확정
- 구독 목록 검색과 상태 필터
- 월별 결제 요약과 결제 캘린더
- 수동 상태 변경 및 메모
- 서비스 결제 페이지 열기
- 로컬 알림

### 2단계 — 안전한 결제 기능

- 결제대행사 및 지원 서비스 조사
- 결제수단 토큰화와 민감정보 비저장 원칙 적용
- 결제처·금액·결제수단 최종 확인 화면
- 중복 결제 방지용 idempotency key
- 결제 성공, 실패, 취소 및 재시도 처리
- 거래 기록과 감사 로그

직접 결제가 지원되지 않는 서비스는 해당 서비스의 공식 결제 페이지로 연결합니다.

### 3단계 — 모바일 확장

- 데스크톱에서 검증된 정보 구조를 모바일 카드 UI로 전환
- 생체인증을 이용한 결제 확인
- 결제일 및 실패 알림
- 데스크톱과 모바일 간 상태 동기화

## Gmail 데이터 처리 원칙

- 필요한 최소 범위의 OAuth 권한만 요청합니다.
- 결제와 무관한 메일 본문은 저장하지 않습니다.
- 추출한 결제 정보에는 원본 메일의 출처와 추출 시각을 기록합니다.
- 자동 추출 결과는 사용자가 확인하고 수정할 수 있어야 합니다.
- 계정 연결 해제 및 데이터 삭제 기능을 제공합니다.
- Google API 정책과 OAuth 앱 검증 요건을 구현 전에 확인합니다.

## 결제 안전 원칙

- 앱 서버에 카드번호와 CVC를 직접 저장하지 않습니다.
- 한 번의 클릭만으로 결제가 실행되지 않게 합니다.
- 금액이나 결제수단이 변경되면 사용자가 다시 확인해야 합니다.
- 중복 요청, 네트워크 재시도 및 부분 실패를 안전하게 처리합니다.
- 실제 결제 기능은 지원되는 결제대행사와 서비스 범위를 검증한 뒤 제한적으로 도입합니다.
- 초기 버전은 공식 결제 페이지 연결을 기본 수단으로 사용합니다.

## 예상 기술 구성

- 데스크톱: Tauri 또는 Electron
- 화면: React + TypeScript
- 로컬 데이터: SQLite
- Gmail: Google OAuth 2.0 + Gmail API
- 백엔드: 최소 권한의 API 서버
- 결제: PCI DSS 범위를 줄일 수 있는 토큰 기반 결제대행사
- 테스트: 단위 테스트, Gmail 파서 회귀 테스트, 결제 샌드박스 통합 테스트

최종 기술 선택은 Gmail OAuth 운영 방식, 결제대행사 지원 범위와 데스크톱 자동 업데이트 요구사항을 검증한 후 확정합니다.

## MVP 완료 기준

- 사용자가 Gmail 계정을 안전하게 연결하고 해제할 수 있습니다.
- 정기결제 후보가 근거 메일과 함께 표시됩니다.
- 사용자가 잘못 탐지된 항목을 수정하거나 제외할 수 있습니다.
- 월별 결제 금액과 상태가 정확하게 집계됩니다.
- 지원되지 않는 직접 결제는 공식 결제 페이지로 안전하게 연결됩니다.
- 실제 결제는 최종 확인, 중복 방지와 실패 복구 절차를 통과합니다.
- 민감정보가 로그나 로컬 데이터베이스에 평문으로 저장되지 않습니다.

## 개발

```bash
pnpm install
pnpm test      # 도메인 단위 테스트
pnpm dev       # apps/web Vite 개발 서버
pnpm build     # 웹앱 빌드
```

`main` 브랜치 push와 PR에서 GitHub Actions CI가 `test`, `typecheck`, `build`를 실행합니다.

루트의 `wallet-cards.html`은 초기 HTML 데모입니다. 새 UI는 `apps/web`을 사용합니다.
