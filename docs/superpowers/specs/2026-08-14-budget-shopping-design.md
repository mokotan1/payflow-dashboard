# 예산 기반 쇼핑 추천 설계

## 목적과 범위

Payflow를 개인의 예산 안에서 구매 후보를 비교하고 판단하도록 돕는 대시보드로 확장한다. 사용자는 월별 예산을 설정하고, 관심 상품의 판매처별 가격을 비교하며, 예산과 목표가에 근거한 추천을 받는다.

이 기능은 결제·송금·자동 구매를 실행하지 않는다. 계좌 연동은 나중 단계의 읽기 전용 조회만 허용하며, 본 설계의 첫 단계에서는 수동 입력, CSV, 익명화된 데모 거래내역을 사용한다.

## 선택한 접근: 로컬 우선의 단계적 MVP

금융 연동, 가격 수집, 추천을 한 번에 실제 서비스와 연결하지 않는다. 먼저 로컬 데이터로 예산·관심상품·추천 경험을 검증하고, 가격 데이터와 계좌 조회를 순차적으로 추가한다.

이 접근은 다음을 보장한다.

- 사용자 거래내역과 예산 정보는 기존 원칙대로 사용자 PC의 로컬 암호화 저장소에만 보관한다.
- 중앙 게이트웨이는 인증과 기기 라우팅만 수행하며, 거래내역·예산·관심상품을 저장하지 않는다.
- 모든 추천은 설명 가능한 결정 규칙과 입력 데이터의 시각을 함께 표시한다.
- 쇼핑몰 가격 데이터는 공식 API 또는 제휴 상품 피드를 우선 사용한다. 약관 확인 없는 스크래핑은 기본 수집 경로가 아니다.

## 사용자 흐름

1. 사용자는 월 총예산과 카테고리별 한도를 설정한다.
2. 사용자는 수동 입력 또는 CSV 가져오기로 거래내역을 추가하고, 필요한 경우 카테고리를 수정한다.
3. 사용자는 관심상품에 상품명, 옵션·규격, 목표가, 우선순위, 예산 카테고리, 구매 예정일을 등록한다.
4. 시스템은 각 상품의 가격 스냅샷을 비교하고, 같은 옵션인지 확인 가능한 정도를 표시한다.
5. 시스템은 남은 카테고리 예산, 고정지출·구독 예약액, 목표가, 가격 정보 신선도를 기준으로 추천 결과와 이유를 보여준다.
6. 사용자는 판매처의 공식 상품 페이지를 연다. Payflow 안에서 결제하거나 결제수단 정보를 입력하지 않는다.

## 구성 요소와 데이터 경계

### 예산 엔진

`Budget`은 월별 총한도와 카테고리 한도를, `BudgetPeriod`는 기간별 사용액과 잔여액을 관리한다. 사용액은 사용자가 수정할 수 있는 거래내역 분류 결과를 합산한다.

### 거래내역 입력

초기 입력원은 수동 입력, CSV, 데모 데이터다. 모든 거래에는 입력원, 발생일, 금액, 카테고리, 분류 신뢰도와 검토 상태를 기록한다. 계좌 연동은 후속 단계에서만 읽기 전용으로 추가한다.

### 관심상품과 가격 비교

`WatchItem`은 사용자가 관심 있는 상품과 목표가를 나타낸다. `PriceSnapshot`은 판매처, 상품 URL, 상품명, 옵션·규격, 배송비 포함 가격, 재고 여부, 수집 시각을 저장한다. 비교 결과에는 동일 상품·동일 옵션인지의 일치 신뢰도를 표시하며, 확신할 수 없으면 최저가로 단정하지 않는다.

### 추천 엔진

추천 엔진은 우선 규칙 기반으로 동작한다. 다음 조건을 모두 만족하면 구매 후보로 추천한다.

1. 관심상품의 예산 카테고리에 남은 예산이 예상 결제금액 이상이다.
2. 구독 등 이미 예정된 고정지출을 제외한 가용 금액이 충분하다.
3. 가격이 사용자 목표가 이하이거나, 목표가 미설정 시 우선순위와 남은 예산 기준을 만족한다.
4. 가격 스냅샷이 신선하고 옵션 일치 신뢰도가 기준 이상이다.

추천하지 않는 경우에도 이유를 명시한다. 예: `쇼핑 예산 2만원 부족`, `옵션 일치 확인 필요`, `가격 정보가 7일 지남`.

## 화면 구성

- **홈:** 이번 달 총예산, 카테고리별 사용액, 남은 쇼핑 여유금, 추천 상품 요약
- **예산:** 기간과 카테고리 한도, 거래내역 가져오기·분류·수정
- **관심상품:** 상품 등록, 목표가, 우선순위, 예산 카테고리, 제외·보관
- **가격 비교:** 판매처별 배송비 포함 예상가, 옵션, 재고, 수집 시각, 공식 상품 링크
- **추천함:** 추천 여부, 근거, 예산 영향, 관심 유지·제외·판매처 열기

모든 화면은 데이터 원본(데모, 수동, CSV, 향후 계좌 연동)과 마지막 갱신 시각을 표시한다.

## 단계별 범위

1. **예산·관심상품 UI:** 데모 데이터로 예산 설정, 관심상품 등록, 규칙 기반 추천과 상태를 구현한다.
2. **거래내역 가져오기:** CSV 형식 검증, 중복 탐지, 카테고리 수정, 로컬 저장을 추가한다.
3. **가격 데이터:** 소수의 공식 API 또는 제휴 피드와 연동하고, 가격 신선도·옵션 일치·실패 상태를 표시한다.
4. **읽기 전용 계좌 조회:** 금융 데이터 제공자의 동의·토큰 보관·해지·최소 범위 요구사항을 별도 계약과 보안 검토 후에 추가한다.
5. **알림:** 가격 하락 또는 예산 초과 상태를 로컬 알림으로 제공한다.

## 실패 처리와 안전 기준

- CSV 형식 오류, 중복 거래, 카테고리 미분류는 사용자가 수정하거나 제외할 수 있어야 한다.
- 가격 조회 실패·오래된 스냅샷·재고 불명은 추천의 신뢰도를 낮추고 명확히 표시한다.
- 계좌 연결이 해제되거나 동기화에 실패해도 기존 로컬 예산과 사용자가 입력한 데이터는 읽을 수 있어야 한다.
- 카드번호, CVC, 계좌 인증정보, 접근 토큰, 원본 거래내역은 로그·테스트 픽스처·중앙 서비스에 평문으로 저장하지 않는다.
- 추천은 금융 자문이나 구매 승인으로 표현하지 않고, 계산 근거를 보여주는 의사결정 보조 기능으로 표시한다.

## 검증 전략

- 단위 테스트: 예산 잔여액, 고정지출 예약, 추천/비추천 조건과 이유
- 계약 테스트: 거래 입력, 관심상품, 가격 스냅샷, 추천 응답 스키마
- UI 테스트: 빈 상태, CSV 오류, 가격 지연, 옵션 불일치, 예산 초과, 공식 링크 열기
- 보안 검토: 로컬 저장 위치, 민감정보 로그·픽스처 유입, 읽기 전용 계좌 권한, 연결 해제·데이터 삭제

## 명시적 비범위

- Payflow 내부 직접 결제, 자동 구매, 카드·CVC 입력 또는 저장
- 약관·인증·보안 검토가 없는 은행 및 쇼핑몰 연동
- 중앙 서비스의 예산·거래내역·관심상품 상세 저장
- 임의의 공개 포트포워딩 또는 사용자의 로컬 노드 공개
